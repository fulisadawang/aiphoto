# 需求清单（二期）

产品初心：解决摄影师拍完之后**大量筛选**和**第一遍修复**耗时的问题。

2026-10-20 起：像素蛋糕按张收费，用户希望**尽量少用像素蛋糕**，大部分照片在本 App 里修完直接交付，只有实在处理不了的才送像素蛋糕。

状态说明：✅ 已确认 · 🟡 待梳理 · ⏸ 暂不做

---

## 1. 修复前后对比 ✅

**目的**：检查 AI 修复的效果——去杂物有没有留痕迹、调色是否过头、皮肤有没有修假。

- **分割线模式**：一张图中间一条竖向分割线，左半边原图、右半边修复后，拖动分割线来回对比。
- **修复后包含全部修复**：去杂物、调色、皮肤柔化、风格一起显示。
- **放大检查**：滚轮或双击放大到鼠标所在位置，拖动平移，可放大到 100%、200%。
- **对比状态下可直接处理**：画笔涂抹去杂物、撤销上一次消除、调右侧修图参数，修改后立即在分割线右侧看到效果。
- **逐张检查**：方向键切换上一张 / 下一张，保持对比状态。
- **入口**：按 `\` 进入 / 退出对比模式（取代现在"整张切换原图"的用法）。
- **切换照片时保持放大倍数和位置**，便于在连拍中检查同一处。

**完成标准**：在实拍上去掉婴儿车后，进入对比模式能放大到 200% 检查消除边缘；在对比状态下补涂一笔并消除，右侧立即更新；方向键能连续翻看已修复的照片。

## 2. 放大查焦与看片辅助 ✅

**目的**：选片时快速判断"焦点对不对、曝光能不能救、有没有拖影"。

- **放大**：操作与对比模式一致——滚轮或双击放大到鼠标位置，拖动平移，快捷键在"适应窗口 / 100% / 200%"间切换。
- **空格一键放大到人脸**（保留现有行为），检测不到人脸时放大到人体。
- **切换照片时保持放大倍数和位置**：放大看孩子眼睛后用方向键连续翻，逐张比较连拍的合焦。
- **小导航图**：放大时角落显示全图缩略，标出当前查看区域，可点击跳转。
- **合焦区域高亮（峰值对焦）**：把清晰的边缘描成彩色轮廓，不放大也能看出焦点落在哪里。快捷键开关，默认关闭。
- **过曝 / 欠曝提示**：死白高光标红、死黑暗部标蓝。快捷键开关，默认关闭。
- **拍摄参数**：在右侧显示快门、光圈、ISO、焦段、镜头。
- **直方图**：在右侧显示 RGB 直方图。
- **相机对焦点**：显示拍摄时相机实际对焦的位置。 `[待调研：需确认能否从佳能 CR3 的厂商数据中读出对焦点；读不出则告知用户后不做]`

**完成标准**：在实拍 0440 上放大到 100% 看孩子侧脸，方向键切到 0441、0442 时停在同一位置；打开合焦高亮能看出焦点在孩子身上而非背景；草帽、白衣服的过曝区域能被标出；右侧能看到快门、光圈、ISO 和直方图。

## 3. 撤销 / 重做 ✅

- ⌘Z 撤销、⇧⌘Z 重做。
- 可撤销：选用 / 淘汰 / 星级；修图参数（一次拖动算一步）；自动调色；风格；去杂物（撤销最近一次消除）；未消除的画笔笔触（撤销上一笔）；同步到本组、套用到全部已选等批量操作（整批算一步）。
- 不可撤销：AI 选片结果（耗时耗额度，不满意可手动改或重跑）。
- 撤销记录只在本次打开期间有效，关闭 App 或换文件夹后清空；选片结果本身照常保存。

## 4. 初修 ✅

**流程**：选完片 → 一键初修（批量、全自动） → 看初修总结 → 在修复前后对比中逐张检查 → 不满意的单张手动补。

### 4.1 一键初修
- 对所有"已选"照片**全自动**处理，不需要事先过目：
  - 自动调色（白平衡、曝光、高光阴影）
  - 套用当前选定的风格（如果有）
  - **轻度皮肤柔化**（有可用人脸时）
  - 去掉 AI 发现的干扰物
- AI 判断干扰物时区分"背景杂物"（推车、杂物、电线、路人、垃圾桶等，**去除**）和"主体相关物品"（孩子手里的玩具、抱着的娃娃等，**不去除**，只在总结里提一句）。

### 4.2 初修总结
- 初修完成后给出总结，**"需要你看一眼的"排在前面**：
  - 去杂物区域较大、建议检查的
  - 初修无法修复的问题（闭眼、模糊、构图等，来自 AI 选片和本地检测）
  - ~~AI 识别到但未去除的主体相关物品~~ → 实测每张亲子照都有草帽、篮子等主体相关物品，全部列入会让每张都"需要看一眼"。改为只在每张的初修记录里写"保留了什么"，不计入需要检查（用户已确认）
- 其余列在"已自动处理"：每张写明做了什么（曝光 +0.3、白平衡校正、皮肤轻度柔化、去掉了右下角推车……）。
- 点总结中的任一条，直接跳到该照片的修复前后对比模式。
- 每张照片右侧也显示它自己的初修记录。

### 4.3 去杂物放到后台排队
- 一键初修中的去杂物和手动涂抹的去杂物，都在后台排队处理，不占住界面，可以继续选片、检查。
- 底部显示进度，如"去杂物：进行中 2，排队 15"；缩略图上标出"修复中"。
- 失败的单独列出原因，可重试。

### 4.4 单张一键去干扰物
- 右侧显示"AI 发现：右下角婴儿车"，点一下自动框出并去掉，不用手动涂抹。

### 4.5 整组一起去杂物
- 在一张照片上涂抹后可选"整组一起去"，同组连拍的其他照片同一位置一起去掉。

**完成标准**：在实拍 6 张上选片后一键初修，全程不阻塞操作；0438、0439 的婴儿车被去掉并出现在"需要你看一眼的"里；每张都有初修记录；从总结点进对比模式能看到修复前后。

## 5. 网格总览 ✅

**目的**：一屏扫完整场照片，快速掌握全局选片和初修进度。

- **入口**：按 `G` 在网格总览和单张大图之间切换。
- **按连拍组排列**：组与组之间有间隔，能看出哪组已选、哪组还没选。
- **缩略图标记**：已选 ✓、淘汰 ✗、AI 推荐 ⭐、问题标签（模糊 / 闭眼等）、初修状态（修复中 / 已修复 / 需要看一眼）。
- **直接操作**：P / X / U 标记、方向键移动，双击或回车进入大图。
- **框选多张一起操作**：鼠标框选或 ⇧ / ⌘ 点选多张后一起选用 / 淘汰，整批算一步撤销。
- **缩略图大小可调**：一屏 20～100 张。
- **顶部统计**：共 N 张 · 已选 · 淘汰 · 待定 · 初修完成。

**完成标准**：按 G 进入网格能看到全部照片按组排列；框选一组后按 X 全部淘汰，⌘Z 一次撤回；双击进入大图。

## 6. 对话改图 ✅（2026-10-20 确认并完成）

**目的**：对单张照片用大白话说要怎么改，AI 动手修改，可以多轮来回调整。

- **入口**：右侧面板一个「对话改图」按钮，点开后在右侧显示对话区和输入框；只作用于当前照片。
- **多轮对话**：每轮 AI 回一句做了什么（如"已把曝光提高 0.3 EV"），下一句在上一步结果上继续改（"还是暗，再亮点"）。
- **AI 自己判断走哪条路**：
  - 去掉指定的东西（"把左边垃圾桶去掉"）→ 框出目标，走现有去杂物流程。
  - 调色调光（"亮一点、暖一点、天空蓝一点"）→ 换算成曝光 / 色温 / 高光等滑块值，非破坏，可再手动微调。
  - 局部重画（"阴天换蓝天""草地补绿"）→ 图片模型重画该区域；效果不稳定，结果需要看一眼。
  - 人像修饰（"瘦脸、美白、去眼袋"）→ 图片模型重画脸部局部；可能改变长相，效果待实测，不满意直接撤销。
- **可撤销**：每一轮都是一步 ⌘Z；修复前后对比（`\`）里能看到对话改图的结果。
- **记录**：对话历史跟着照片保存在选片记录里，下次打开还在。
- **模型**：理解指令和定位用 `group/auto-gemini-3-8-flash`（设置里「对话改图模型」可改），出图用 `/images/edits`（gpt-image-2），都走本机 Magpie。
- **实现中补充的规则**（实拍验证后加的）：
  - 位置校正：人像修饰对齐到本地检测的人脸；其他物体放大局部让模型再确认一次，确认不到就不执行并说明。
  - 重画范围限制：局部图放大回原尺寸超过 3 倍不执行（天空整片重画放大约 6 倍，树梢明显变糊）；大面积改色由模型改用整体调色近似。
  - 输入框有焦点时，选片快捷键（P/X/Z/空格/方向键等）不响应。

**完成标准**：在实拍上依次说"亮一点""把右边的路人去掉""再暖一点"，三轮都正确生效，⌘Z 能逐轮撤回；关掉 App 再打开，对话记录仍在。

### 对话改图验收（2026-10-20）

- 离屏（`raw+jpg+2` 实拍）：0464「亮一点 → 把右边的路人去掉 → 再暖一点 → 天空蓝一点」四轮都正确，路人去除干净，天空按说明改用整体调色；0499「把池塘边的小狗去掉 → 帮她去一下黑眼圈」小狗去除干净、眼周提亮且长相不变；0490「脸瘦一点」轻微收窄、长相不变。
- 模型对比：同一句「把池塘边的小狗去掉」，`group/auto-auto` 3 次都框到旁边木门，`group/auto-gemini-3-8-flash` 3 次都框准。
- 界面（接管屏幕）：右侧入口打开面板、真实键盘输入 xpz 和空格不触发快捷键、回车发送、后台去除完成后回写「已完成」、⌘Z 逐步撤回（调色和去除各一步，只回退对应字段）、关掉 App 重开对话记录仍在、关闭面板回到修图面板。
- 已知局限：一轮里既调色又去除时算多步撤销；撤销后对话里那条回复仍保留（不会标记"已撤销"）；人像修饰效果较轻，放大约 2.7 倍略软。

## 7. 自定义预设与 AI 描述 ✅（2026-10-20 开发完成，离屏和界面验证通过）

**目的**：把自己常用的修图方式存成预设，初修时统一按预设修，并能用文字告诉 AI 这场要怎么修。

- **预设内容**：名字；风格及力度；磨皮力度；对比度、自然饱和度、高光、阴影、色调；**给 AI 的描述**（如"整体通透偏暖，肤色红润不要偏黄；背景杂物都去掉，地上的落叶和南瓜保留"）。
  - **不含曝光和色温**（用户确认）：明暗由自动调色按每张光线决定，冷暖由描述或风格决定。
- **创建与管理**：当前照片修好后「存为预设」（取上述字段，不取曝光色温）；或在预设管理里新建、编辑、删除。预设全局保存，所有文件夹共用。
- **默认预设**：可设一个默认，一键初修时自动选中，也可临时换。
- **开始初修前填写本场诉求**（用户确认需要）：弹出填写框，自动带出所选预设的描述，可修改或补充只用于本场的话（如"这场逆光，人脸提亮一些"）；不强制必填，留空则只按预设和自动调色。
- **AI 怎么按描述修**（描述同时作用于调色和去杂物）：
  - 调色：AI 先看本场几张代表照片，把描述**换算成一组整场统一的调整**（如暖 +400K、对比 +0.1、饱和 +0.15），并在界面上说明它的理解；每张照片先按自身光线自动校正曝光和白平衡（方案 A），再叠加预设参数和这组统一调整。保证整场颜色一致、亮度各自正常。
  - 去杂物：每张照片定位杂物时都带上描述，按描述去除或保留。
  - 对话改图：带上该照片所用预设的描述。
- **套用到已修过的照片**（用户确认）：调色按新预设重做，去杂物和合成结果保留；单张可一键套用；整批套用算一步撤销。

**完成标准**：建一个「秋日暖调」预设（对比 +0.1、磨皮 30%、描述"整体偏暖通透，保留地上落叶"），对一场实拍一键初修：每张亮度各自正常、整体统一偏暖；界面显示 AI 对描述的理解；AI 去杂物时没有去掉落叶；对已修过的照片再套用另一个预设，颜色更新而去杂物保留；⌘Z 一次撤回。

## 8. 多图合成 ✅（2026-10-20 开发完成，离屏和界面验证通过）

**目的**：把一张照片里的东西（鸭子、人、物品）挪到另一张里；包括全家福有人闭眼时，从相邻连拍里换一张睁眼的脸。

- **选取**：在来源照片上点一下目标，用系统的「提取主体」在本机抠出（免费、不上传）；抠不准时可用画笔补选或擦除。也可在对话里说"把这张的鸭子拿过来"。
- **放置**：目标以图层叠到当前照片上，拖动调位置、拖角调大小、可水平翻转。
- **两种来源都支持**（用户确认）：
  - 同一场景的连拍：自动对齐到同一位置，适合换脸、换局部，基本看不出痕迹；
  - 完全不同的两张图：手动放置，效果取决于光线和角度是否接近。
- **融合**：自动把目标的亮度和颜色调到与当前照片一致；仍显假时，可让 AI 只重画目标边缘一圈，补影子、对齐光线。
- **非破坏、可撤销**：合成结果和去杂物一样单独保存，可对比前后（`\`），可撤销。
- **限制**：光线方向、拍摄角度、远近差很多时效果明显下降；细碎物体（细绳、发丝边缘）抠图不稳，需要用实拍验证。
- **实现中确定的细节**（用户确认：只从当前这场选来源；完成后定下来，不满意撤销重做；连拍和自由放置一起做）：
  - 来源列表里同一组连拍排在最前；同组或前后 60 秒内的照片先尝试自动对齐。
  - 连拍对齐先整体配准、再在主体周围局部配准，按完整透视变换贴回（只做整体配准时视差会让近处窗框错开）。
  - 连拍换人时把当前照片里对应的人也盖住；认不出对应的人（被窗框挡住等）就把来源主体外扩 15%，用来源里干净的背景盖住原来的人。
  - 合成结果和去杂物一样存成修补块，可撤销、可对比。

**完成标准**：在实拍上把一张里的人或动物移到另一张同场景照片中，放大到 100% 看边缘自然；全家福连拍里把闭眼的人换成睁眼；不同场景的两张图也能完成放置和融合，并能撤销。

### 自定义预设离屏验收（2026-10-20，`raw+jpg+2` 实拍）

- 本场诉求「整体通透偏暖，肤色红润不要偏黄；背景杂物都去掉，地上的落叶保留」：AI 理解为「色温 +300～350K、色调 +4～5、阴影 +0.10」，三次结果一致；套到 6 张照片上整场统一偏暖，曝光各自保留（+0.00～+0.50 EV）。
- 去杂物描述：0499 不写描述时有一次把池塘边的小狗当成「木屋左侧探出的动物头」去掉；写「池塘边的小狗保留」后两次都保留。
- 验收中发现并修正：
  - 自动调色的高光保护按亮度算，拦不住饱和红墙溢出（0477 红墙溢出 0.9% → 12%）→ 改按最亮通道，降到 0.8%。
  - 预设加诉求叠加后红房子特写整片红墙到顶、木板纹理消失 → 新增溢出保护，新增溢出超过 3% 时本张调整减弱到 50% / 25%，并写进初修记录。
- 界面（接管屏幕）：预设管理新建、改名、设默认、写描述、调对比度均即时保存；修图面板「套用预设」到当前照片后参数正确（自动曝光 + 色温 +350K、色调 +5、阴影 +0.1、对比 +0.13），撤销菜单显示「撤销「套用预设「秋日暖调」」」；一键初修窗口自动选中默认预设并带出描述，可从中打开预设管理；「存为预设」只存相对自动调色的偏移、不存曝光色温；在描述框打字不触发选片快捷键。
- 小问题：初修记录里白平衡写「偏暖 → 中性」，与随后的「按本场诉求偏暖」读起来矛盾，可后续调整措辞。
- 已知问题：验证时 Magpie 网关整体很慢（只回复「你好」也要 100～200 秒），理解本场诉求用了 2 分钟以上；网关正常时预计十几秒。

## 11. 本地人像修复 🟡（2026-10-20 提出并确认；已开发，待用户验收）

**目的**：常用的人像小修在本机即时完成，免费、照片不出电脑、整批效果一致；不用每次等 AI 重画几十秒。

- **磨皮升级**：改用开源的 YUCIHighPassSkinSmoothing（Core Image，MIT 许可，高低频分离、保留毛孔纹理），只作用于皮肤区域（Vision 人脸 / 人物分割定范围，不用颜色猜，避免红墙、红衣服被误磨）。
- **眼睛**：去黑眼圈 / 眼袋（眼下局部提亮、去偏色）、提亮眼睛。
- **牙齿**：美白（嘴部区域降黄提亮）。
- **轻度美型**：瘦脸、大眼，用 Vision 人脸关键点做局部变形（算法按公开论文《Image Deformation Using Moving Least Squares》自己实现，思路可参考 GPUPixel，Apache-2.0）；只做轻度，背景不跟着变形。
- **使用方式**：右侧修图面板一组滑块，拖动即时预览；可存进预设，一键初修批量套用；多人合照默认对所有检测到的脸生效；在大图上点某张脸可以只调这个人（用户 2026-10-20 确认）。
- **不使用**任何来自像素蛋糕逆向材料（含所谓「白皮书」）的代码、参数、着色器或配置。
- **参考来源（2026-10-20 核实）**：
  - 磨皮：[YUCIHighPassSkinSmoothing](https://github.com/YuAo/YUCIHighPassSkinSmoothing)（MIT，Core Image，2016 年但算法仍是标准做法）。
  - 大眼、瘦脸、亮眼、白牙：参考 [swift-face-beauty](https://github.com/arraypress/swift-face-beauty)（MIT，Vision + Core Image；要求 macOS 26，需改写兼容 macOS 15；项目很新、未经验证，瘦脸大眼用的是 CIBumpDistortion，不够自然时升级为 MLS 变形）。
  - 验收方法借鉴 [portrait-engine](https://github.com/chacalra/portrait-engine) 的思路：检查修改区域外泄漏、纹理保留、五官关键点位移（该项目为专有许可，只借鉴思路，不用代码）。

**完成标准**：在能看清孩子脸的实拍上，每项单独拖动都能即时看到效果、长相不变、发丝和背景不受影响；放大到 100% 皮肤保留纹理；预设批量套用结果一致。

### 15.1 本地去杂物（LaMa）——做什么

- 用开源 LaMa（`advimman/lama`，Apache-2.0）的 Core ML 版本在 Mac 本机运行；不上传、不花钱。

  - 备选：用 `mallman/CoreMLaMa` 的脚本自己转换；本机太慢时换 `Picsart-AI-Research/MI-GAN`（MIT，更轻）。
- 推车、路人、电线、垃圾桶这类小到中等的杂物默认走本机；大面积、需要"想象"内容的走 gpt-image-2。本机修完不满意可以点「用 AI 重画这一处」。
- 结果仍存成修补块，撤销、对比、导出都不变；后面的祛瑕疵、美体补背景、合成时盖掉原来的人都用它。

### 15.2 祛瑕疵——做什么（2026-10-21 细化，开发前再确认一次）

**目标**：孩子脸上的蚊子包、抓痕、鼻涕、饭粒、磕碰，大人的痘，在 App 里点一下就修掉，修完看不出痕迹、毛孔和细绒毛还在；痣和雀斑默认不动。

**两种修法，按斑点大小自动选**：
- **小斑点（直径 ≤ 脸宽 4%，绝大多数情况）：频率分离修补，纯 Core Image，即时出结果。**
  1. 底色：把斑点挖掉，用"归一化卷积"从四周一圈插值出平滑底色（模糊(图×(1−蒙版)) ÷ 模糊(1−蒙版)），斑点颜色和明暗一起被周围皮肤替代。
  2. 纹理：从同一张脸、斑点附近找一块"供体"皮肤（8 个方向、距离 2～3 倍半径，取底色最接近且全在皮肤蒙版里、不碰五官的一块），只借它的高频（毛孔、细纹），加到第 1 步的底色上。
  3. 圆形羽化贴回。不会糊（纹理是真皮肤的），也不会有色块（底色来自四周）。
- **大块（> 4% 脸宽，或用户用画笔涂的不规则区域，如一大片鼻涕、擦伤）**：生成本机 LaMa 修补块（第 15.1 节）。脸上的小块正是 LaMa 擅长的尺寸；不满意可「用 AI 重画」。

**自动找斑**（只列出，不自动修）：
- 范围：第 11 节的脸部皮肤蒙版（脸轮廓 + 额头，按本脸肤色筛过），再挖掉眼、眉、嘴、**鼻孔**（需要给 `FaceShape` 补鼻子关键点，旧记录打开时补测，和第 11 节做法一样）。
- 检测：在脸部裁图（缩到脸宽 512 像素）上做两种"高斯差"：明度比周围暗（痘印、淤青、蚊子包的阴影侧）、红度（R−G）比周围高（蚊子包、抓痕、痘）。连通区域直径限在脸宽 0.8%～6%，太细长的（头发丝、睫毛）排除。
- 痣的处理：规则分不清痣和斑（都是暗、圆、小）。所以结果全部列出，在大图上画圈，逐个点「修 / 保留」；可以「全部修」。
- 预计误报：发丝阴影、眼镜框边缘、嘴角阴影。验收时你看一遍，误报多就收紧阈值。

**数据**：`EditSettings.blemishes: [BlemishSpot]?`（归一化中心、半径、来源 手动 / 自动；大块的在修补块里）。预览和导出用同一份数据，撤销沿用修图参数类。

**渲染顺序**：修补块 → **祛瑕疵** → 人像修复（磨皮等）→ 风格 → 调色。先祛瑕疵再磨皮，磨皮的暗斑提亮才不会和修补叠加出亮斑。

**界面**（人像工具里新增「祛瑕疵」一节）：
- 「点修」开关：开着时在大图上点一下修一个点，圈的大小跟画笔滑块走；按住拖动是涂抹，松手后交给 LaMa。
- 「自动找斑」按钮：找到的点在大图上画圈，旁边列表显示「找到 N 处」、「全部修」「全部清除」。
- 每个点可以单独删除；⌘Z 撤销。

**验证**：
- 需要你提供能看清孩子脸、有蚊子包 / 抓痕 / 饭粒的近照（现有测试照片里只有 0490 一张近脸，而且脸很干净）。
- 沿用第 11 节的指标：修复区以外像素不变；修复区纹理强度与周围比值 0.8～1.2；修后斑点与周围肤色差显著下降。
- 自动找斑：你逐张看列出的点，统计漏报 / 误报。

**风险**：
- 斑点在脸的边缘、靠近五官时供体难找：找不到合格供体就只用底色，并在点上标「可能不自然」。
- 合影小脸（脸宽 < 150 像素）不做自动找斑，只能手动点修。

### 15.3 技术方案

**去杂物接入（改动小）**：现有 `CleanupEngine.run` 已经是"裁正方形局部 → 缩小 → 补全 → 放大回原尺寸 → 按蒙版外区域校色 → 只取涂抹区域羽化贴回"，补全由 `InpaintProvider` 完成。新增一个本机实现即可：
- `LaMaInpainter: InpaintProvider`：把局部图和蒙版缩放到 800×800，调用模型，返回结果。模型只加载一次（常驻，峰值约 600 MB），计算单元用转换时验证过的 `.all`。
- 补颗粒：LaMa 补出来的区域比相机 JPG 平滑，贴回前按蒙版外的高频强度加同等颗粒，避免一块"塑料感"。
- 选择引擎：`InpaintService.makeProvider` 按用途和面积决定——去杂物、一键初修的去杂物、合成时盖掉原来的人走本机；对话改图的「重画」和合成融合要按文字指令画新内容，LaMa 做不到，仍走 gpt-image-2。本机模型没下载或出错时退回 gpt-image-2。
- `CleanupPatch` 加可选字段记录用的是本机还是 AI（兼容旧记录），用于「用 AI 重画这一处」和用量统计。

**模型下载与管理**：
- 新增本地模型管理：第一次用到时提示下载，显示大小和进度；下载后校验 SHA-256，`MLModel.compileModel` 编译后存到 `~/Library/Application Support/AIPhoto/models/`；设置里可以查看状态和删除。
- 模型不打进安装包，安装包大小不变；Sparkle 更新不影响已下载的模型。

**祛瑕疵**：
- 数据：`EditSettings` 新增可选的修复点列表（归一化位置、半径、方式），旧记录不受影响。
- 渲染：在人像修复流程里、磨皮之前执行；小点用频率分离（低频取周围一圈的平均色，高频从同一张脸附近的皮肤借），大点生成 LaMa 修补块。
- 自动找斑：在皮肤蒙版里用"高斯差"找局部偏暗 / 偏红的小块，直径限定在脸宽的约 1%～5%【待实测后定】，排除五官区域；结果只列出，不自动修。

**界面**：
- 去杂物工具：画笔涂完后有「本机去除」（默认）和「用 AI」两个按钮；每个修补块可以「用 AI 重画这一处」。
- 人像工具：新增「祛瑕疵」——点修模式和「自动找斑」按钮，找到的斑点在大图上画圈，逐个勾选「修 / 保留」。
- 设置 › AI 服务：新增「本机模型」卡片（已下载 / 未下载、大小、删除）。

### 第 1 阶段可行性验证结果（2026-10-21）

- 模型：Hugging Face `mlboydaisuke/coreml-zoo` 的 `lama/LaMa.mlpackage.zip`，196,237,256 字节，SHA-256 `b57b8451a1a86c00aea52d75230fb5f49d3076eec67403192758c9d2b59c0e69`（与页面一致）。输入 `image`（800×800 彩色）+ `mask`（800×800 灰度，白色为要补的区域），输出 `output`（800×800 彩色）；最低 macOS 12；编译后 207 MB。
- 速度和内存：加载 0.3～1.6 秒；单处补全 0.3 秒左右（第一次预热 2.3 秒），gpt-image-2 每处 22～36 秒；进程内存峰值约 0.9～1.2 GB。
- 效果（5 张实拍 9 处，与 gpt-image-2 并排对比）：
  - 好：小物体、简单背景——小屋窗里的落地灯、地上的白色容器、天空里的电线；天空这一处比 gpt-image-2 更干净（后者涂出一块深蓝）。
  - 差：中到大面积、背景纹理复杂——0485 的路人加手推车、0438 的婴儿车、0462 的桌子，补出来是一片带彩色噪点的糊块，明显不如 gpt-image-2。
  - 排查：GPU 和纯 CPU 结果相同（不是精度问题）；输入里先把要补的区域涂黑结果不变（模型内部已处理）。判断是这个模型在大面积复杂纹理上的固有局限，不是接入错误。是原版 LaMa 就这样，还是这个转换版变差了，需要装 PyTorch 跑原版对比才能确定。
- 结论：本机 LaMa 只适合小面积（电线、小杂物、祛瑕疵这类）；路人、推车这类常见杂物仍需 gpt-image-2。省钱幅度比预期小，接入方式待用户决定。

### 第 2 阶段：接入本机去杂物（2026-10-21，用户确认"LaMa 只用于小面积"）

- 模型放到本仓库 Release `models-lama-v1`（附 Apache-2.0 许可全文），App 第一次用时下载 → 校验 SHA-256 → 编译 → 存到 Application Support；去杂物工具和「设置 › AI 服务 › 高级」里都能下载 / 删除并看进度。
- 自动分流：涂抹面积 < 画面 0.3% 且局部图缩到 800 不超过 1.5 倍才走本机（按第 1 阶段实拍标定：桶、落地灯这类 0.15% 以下的干净，0.6% 以上的推车、桌子补成糊块），其余和对话改图的重画、合成融合仍走 gpt-image-2；本机出错自动退回云端；云端没配置时本机能做的照样做。
- 本机结果补颗粒（强度按周围原图估计并封顶），修补块记录"本机"和涂抹，最近一处是本机补的可以「用 AI 重画上一处」。
- 验证：
  - 端到端安装成功（从 GitHub 下载约 9 分钟，校验通过）。
  - 小桶走本机 2.4 秒（含预热），婴儿车自动走 AI 36 秒。
  - 「用 AI 重画上一处」替换掉本机那一处，只剩 1 处。
  - 颗粒修正前出现满屏白点，修正后正常。
- 已知问题：一键找杂物给的是物体外框画成的圆，比手涂大。即使小于 0.3%，背景是枯草、灌木、铁丝网时，本机结果在 100% 放大下能看出发糊、有块感。建议一键初修的自动去杂物仍全部走 AI，手动涂抹的小块走本机（待用户决定）。

**完成标准**：
- 去杂物：同一批实拍里，小到中等杂物的本机结果与 gpt-image-2 对比，肉眼看不出明显差异；单处修复在本机几秒内完成；修复区域以外像素不变；这些操作不再产生出图费用。
- 祛瑕疵：在能看清孩子脸的实拍上，点一下能去掉蚊子包、抓痕、饭粒这类小瑕疵，纹理保留（沿用第 11 节的漏改和纹理指标）；自动找斑的误报你看一遍可接受。
- 记录模型大小、单次耗时、内存占用。

## 16. 少送像素蛋糕的后续规划 📝（2026-10-21 逐项想清楚做法；每项开发前单独确认一次）

用户确认的顺序：1 本机去杂物（第 15 节）→ 2 祛瑕疵（第 15.2 节）→ 3 孩子和大人分开 → 6 皮肤补全 → 4 液化和 5 美体 → 7 局部调整 → 8 分流。

### 16.0 先打的公共地基（不单独发版，随第一个用到它的功能一起做）

现在的渲染入口是 `EditSettings.apply(to:faces:)`：只知道这张照片的参数和人脸，预览和导出共用。后面几项需要它不知道的东西，所以先统一补三样：

1. **渲染上下文 `RenderContext`**：替代现在只传 `faces`。带上人脸、本场的人物设置（第 3 项）、人物蒙版和人体关键点（下一条）。预览、导出、对话改图的预览都从这里拿，保证三处结果一致。
2. **人物蒙版和人体关键点缓存**：
   - 用 Vision 的 `VNGeneratePersonInstanceMaskRequest`（每张最多 4 人，合成功能已在用）和 `VNDetectHumanBodyPoseRequest`（19 个关节点），按需计算。
   - 存在照片文件夹 `.aiphoto/people/<照片>.json` 和 `.png`（长边 1024）。不在打开文件夹时全量算（几百张太慢），第一次用到时在后台算。
   - 第 3、4、5、6、7 项都用它。
3. **鼻子关键点**：`FaceShape` 补鼻子和鼻孔轮廓（可选字段，旧记录打开人像工具时补测），第 2 项用来避开鼻孔，第 4 项瘦鼻也会用到。

### 16.3 孩子和大人分开设置

**要解决的事**：同一场里孩子只要祛瑕疵和轻磨皮，妈妈要瘦脸、瘦身、去黑眼圈。现在只能"所有脸一样"或"一张张点"，几百张做不过来。

**做法：先认出"谁是谁"，再按人设力度。**
- **年龄段**：AI 选片本来就把照片发给模型。在提示里列出 Vision 检测到的每张脸的位置（编号 + 归一化框），让模型给每张脸标「孩子 / 大人 / 老人」，不用模型自己找脸，避免对不上。只有送审的照片（每组前几张）能拿到；其他照片靠下面的"同一个人"传过去。
- **同一个人**：一场拍摄里大家衣服不变。对每个人取"脸 + 上半身"裁图（用人物蒙版和人脸框），算 Vision 图像特征（`VNGenerateImageFeaturePrintRequest`，分组已在用），全场聚类成「人物 A / B / C」。不用 InsightFace 这类限制商用的人脸识别模型。
- **按人设力度**：每个人一套人像参数（磨皮、黑眼圈、瘦脸……以及后面的美体、皮肤补全），整场自动套用。优先级：这张照片里单独调过的脸 > 这个人的设置 > 年龄段默认（孩子默认只轻磨皮 0.2、不瘦脸不大眼）。

**数据**：`Session` 新增 `people: [PersonProfile]?`（编号、名字、年龄段、人像参数、代表缩略图）；`FaceInfo` 新增可选 `personID`。都是可选字段，旧记录不受影响。

**界面**：人像工具顶部改成人物条：每个人一个头像（取最清楚的一张脸），标年龄段，点头像调这个人的力度；可以改名字、改年龄段、**合并两个人**（被拆开了）、**把某张脸移到另一个人**（认错了）。

**验证**：用实拍统计聚类正确率（人工核对每张脸归属）；孩子和大人设置不同力度后，抽查全场照片套用是否正确。

**风险和取舍**：
- 兄弟姐妹穿同款衣服、换外套的场次会认错 → 必须有合并 / 移动的手动修正，聚类只是起点。
- 背影、侧脸没有人脸 → 不参与人像修复（本来也修不了），不影响。
- AI 标年龄段要多花一点理解费用，但不多发请求（随选片一起）。

**待确认**：孩子默认力度（建议只磨皮 0.2、祛瑕疵自动找斑提示，其他都 0）；老人默认（建议同大人但不瘦脸）。

### 16.6 皮肤补全

**做法：只动"底色"（低频），纹理（高频）不动**，这是不糊、不假的关键。皮肤范围沿用第 11 节的蒙版（脸轮廓 + 本脸肤色筛选），扩大到脖子和手臂时用"人物蒙版 ∩ 与这个人自己肤色接近"的区域，红墙、红衣服不在人物蒙版里或颜色差太远，不会被误修。
- **去油光**：在皮肤里找比周围亮、饱和度低的反光区（额头、鼻尖、脸颊），把它的底色往周围皮肤的底色拉，纹理保留。滑块 0～1。
- **去红、肤色均匀**：把底色的颜色往这张脸的平均肤色拉（只拉色度不拉明暗）。孩子的红脸蛋是自然的，滑块默认 0、上限做软，避免把孩子修成"粉底脸"。
- **整场肤色一致**：每个人（第 3 项）选一张作参考肤色，其他照片里这个人的皮肤底色微调过去，调整量封顶，避免和自动调色打架。依赖第 3 项。
- **扩大到脖子和手臂**：开关，默认开；只用于上面三项和磨皮。

**数据**：人像参数里加 `shine`、`redness`、`evenness`；整场一致的参考记在人物设置里。

**验证**：沿用第 11 节的漏改 / 纹理指标；红墙、红衣服实拍（`raw+jpg+2` 里有）确认不误修；油光要你提供有反光的大人近照。

**风险**：皮肤蒙版在逆光、强阴影脸上会漏；肤色差太大的光线下（树荫半边脸）整场一致会拉偏 → 封顶 + 可以单张关闭。

### 16.4 手动液化

**做法**：
- 四种画笔：推（往拖动方向推）、膨胀、收缩、复原（擦回原样）。笔触存成数据（类型、点、半径、强度），非破坏、可撤销、换参数重渲染。
- 渲染：把所有笔触累加成一张"位移图"（长边 1024，存每个像素该从哪里取色），再用一个采样内核按位移图取原图像素。现在的瘦脸内核是固定几个控制点，液化笔触数量不定，所以改成位移图方式；瘦脸、大眼以后也可以并进来。
- 保护背景：默认把位移乘以人物蒙版（羽化），门框、墙线不跟着弯；可以关掉（例如推衣服边缘时）。
- 拖动时先用低分辨率预览，松手后全尺寸。

**界面**：修图工具栏新增「液化」：四个画笔、大小、强度、「保护背景」开关。拖动需要自定义画布交互，验证时要接管屏幕。

**验证**：直线物体（门框、窗框）在保护背景开着时形变 < 1 像素；撤销 / 重做正确；导出与预览一致。

**风险**：位移图分辨率不够时大幅度推会出锯齿 → 限制单笔强度，提示"多推几次"。

### 16.5 美体（瘦身、瘦腰、瘦手臂、长腿，只对大人）

**做法**：
- 用人体关键点（肩、肘、腕、髋、膝、踝）确定每段身体的中线，用人物蒙版找到轮廓；把轮廓点沿垂直于中线的方向往里收，生成位移图（复用第 4 项的位移渲染）。
- **只变形人物这一层**：人物收窄后露出的背景，用本机 LaMa 补（露出的是贴着人物边缘的细条，正好是小面积）；背景本身不变形，直线不会弯。
- 长腿：只在两个脚踝都在画面里时做，把髋以下竖直拉长（≤ 5%），脚下地面同步拉长（地面一般纹理简单）。
- 只对第 3 项标为「大人」的人生效；孩子不做。

**验证**：门框、栏杆直线不弯；人物边缘没有双边、没有背景糊块；拉腿后脚和地面衔接自然。需要大人全身实拍。

**风险和取舍**：
- 多人贴在一起（抱孩子）时人物蒙版会粘连，收身会带动孩子 → 检测到重叠时只做脸部，不做美体，并提示。
- 宽松衣服的轮廓不是身体轮廓，收太多会变形 → 力度上限保守。
- 阿里 FlowBasedBodyReshaping 没有许可证，不用；算法参考 Moving-Least-Squares（MIT）自己用 Swift 写。

**依赖**：第 3 项（判断大人）、第 4 项（位移渲染）、公共地基 2（人物蒙版 + 关键点）、第 15.1 节（补背景）。

### 16.7 局部调整和基础工具

**做法**：
- **局部范围**：人物 / 背景（人物蒙版）、圆形、渐变、画笔四种，可以叠加多个，每个范围有自己的曝光、对比、饱和、色温、清晰度。典型用法：人物提亮、背景压暗。
- **曲线**：明度曲线 + RGB 分通道（Core Image 的色调曲线）。
- **HSL**：8 个色相段各自调色相 / 饱和 / 明度，用一个颜色内核按色相权重混合。红色段会影响红房子、红衣服，界面上提示。
- **裁剪拉直**：裁剪框 + 角度；Vision 的 `VNDetectHorizonRequest` 自动找水平线给建议角度。
- **暗角**、**导出锐化**（见第 8 项）。
- **天空**：Vision 没有天空分割；先用"画面上部 + 偏蓝或很亮 + 纹理少"的规则做蒙版，认不准就用画笔。
- 渲染顺序：修补块 → 祛瑕疵 → 人像 → 风格 → 全局调色 → 曲线 / HSL → 局部调整 → 液化 / 美体 → 裁剪旋转 → 暗角。

**数据**：`EditSettings` 新增 `curves`、`hsl`、`local: [LocalAdjustment]`、`crop`；都是可选字段。

**界面**：修图工具栏新增「局部」和「裁剪」两个工具；「调色」里加曲线、HSL 折叠区。

**验证**：预览和导出一致（同一套渲染）；裁剪后去杂物、人像的坐标仍对（它们存的是原图归一化坐标，裁剪放在最后）。

**风险**：工具一多，修图面板会挤 → 沿用竖向工具栏，一次只显示一个。

### 16.8 导出与分流（决定最后送几张）

**做法**：
- **导出选项**：长边尺寸（原尺寸 / 4000 / 2048 / 自定义）、导出锐化（屏幕 / 冲印，按导出尺寸自动换算强度）、命名规则（原文件名 / 日期_序号 / 自定义前缀）、JPG 质量；导出改成后台排队，有进度、可取消（沿用 AI 选片的取消机制），不再占住界面。
- **送像素蛋糕标记**：AI 选片时顺带返回「需要送修的原因」（衣服褶皱、眼镜反光、明显碎发），只对已选照片；你也可以手动标记并写原因。网格和胶片条上显示角标，筛选器加「送修」。
- **导出送修照片**：只导出带标记的照片。
- **接回（新做）**：「导入修好的成片…」选文件夹，按文件名对应回照片；对应上的照片记为"外部成片"，预览显示它、导出时直接复制它，不再套用 App 里的修图。
- **初修总结**：加一句「本场交付 N 张，送像素蛋糕 M 张」。

**数据**：`Photo` 新增可选 `handoff`（原因、来源）和 `finishedURL`。

**验证**：导出尺寸、锐化、命名按设置生效；送修标记往返一遍（导出 → 改名后修好 → 接回）全部对得上。

**待确认**：像素蛋糕要的是 RAW（CR3）还是 App 修好的 JPG，或者两者都要；修好的成片是否会改文件名。

### 第二场实拍验收（2026-10-20，`raw+jpg+2`，25 张 CR3+JPG）

- 分析 3 秒；AI 选片 36 秒，16 组推荐 13 张；一键初修 13 张 281 秒，期间界面不被占用。
- 验收中发现并修正：
  - 同一连拍被拆成多组 → 同场景 30 秒内、画面差异小的照片归为一组。
  - 远处小脸量不到睁闭眼 → 量不到时按高分辨率裁出脸部重测，9 张脸全部测到。
  - 白色窗框被标"过曝" → 死白面积超过 20% 才提示。
  - 自动调色发灰、红房子溢出、偏艳 → 修图底图改为相机 JPG（只有 RAW 时才解码 RAW）；提亮受高光保护（新增死白不超过 2%），提不够的用阴影补；无人脸的场景只在明显过暗/过亮时调整；去掉自然饱和度。
  - 定位模型把"远处围栏"列为杂物 → 围栏、树木、草地等景物一律不去除。
- 本场没有闭眼样本，闭眼检测仍待补测。

### 界面验收（2026-10-20，接管屏幕）

- 通过：修复前后对比（\ 键、拖动分割线、放大时两侧同步）、Z 键缩放循环、空格放大到人脸、切换照片保持放大、合焦高亮、过曝提示、人脸框与相机对焦点、撤销/重做（菜单显示「撤销「淘汰」」等具体名称）、初修总结点击跳到对比、网格总览框选 → X 批量淘汰 → 一次撤销恢复、单张一键去干扰物（后台排队，界面不被占用）。
